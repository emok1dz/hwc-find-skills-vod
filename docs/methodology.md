# 华为云技能查找与 VOD 反馈：标准化方法论

> 适用对象：任何需要用 AI 智能体操作华为云服务的开发者。
> 核心原则：**先找现成技能，不重复造轮子；找不到或不好用，就把问题沉淀成结构化问题单，让缺口变成产品改进的输入。**

## 一、五步流程

| 步骤 | 目标 | 做法 | 完成标准 |
| --- | --- | --- | --- |
| ① 描述意图 | 让检索有的放矢 | 用“服务 + 动作”描述需求，例如“管理 ECS”“查询 OBS 桶”“分析账单” | 一句话能说清“对哪个服务做什么” |
| ② 检索技能 | 在技能库中定位候选 | 交给 `huawei-cloud-find-skills`：按**关键词**（服务名/动作）检索，范围太大时加**类目**（computing、storage、network、bss……）收窄 | 得到按相关度排序的候选列表 |
| ③ 评估候选 | 选出最合适的那个 | 查看候选技能的 SKILL.md 详情，逐项核对：覆盖的服务和操作、是否只读、是否需要 AK/SK 与哪些权限、是否会产生费用 | 选定 1 个技能，并说明选择理由 |
| ④ 安装与使用 | 用技能完成任务 | 用规范技能名安装（`npx skills add …#master --skill <name> -y`），然后按技能说明执行 | 技能出现在已安装列表，任务结果可验证 |
| ⑤ 缺口反馈 | 把问题变成改进输入 | 遇到“找不到技能 / 技能缺能力 / 执行报错 / 体验差”时，交给 `huawei-cloud-vod-collector` 生成问题单，授权后同步为 GitCode Issue | 生成 `VOD-YYYYMMDD-NNNN` 问题单，Issue 链接可访问 |

## 二、检索技巧

| 场景 | 推荐提法 | 说明 |
| --- | --- | --- |
| 已知服务 | “华为云有没有管理 **ECS** 的技能？” | 服务名是最强的检索信号 |
| 只知道领域 | “华为云**网络**相关的技能有哪些？” | 按类目浏览 |
| 只知道任务 | “我想**查询代金券余额**，用哪个技能？” | 用动作 + 业务对象描述 |
| 结果太多 | 加上动作或类目限定，如“ECS **查询**”“computing 类目” | 收窄范围 |
| 结果为 0 | 换同义词（云主机/ECS/弹性云服务器），仍为 0 → 进入第 ⑤ 步 | 判定为需求缺口 |

## 三、候选技能评估清单

- [ ] 覆盖目标服务和目标操作（例如只读查询还是创建/删除）
- [ ] 权限最小化：需要的 IAM 权限是否只覆盖必要操作（看 `references/iam-policies.md`）
- [ ] 费用透明：是否会创建计费资源
- [ ] 凭证安全：AK/SK 是否只通过环境变量或 CLI 配置读取，不写进文件
- [ ] 可验证：是否提供验证方法（看 `references/verification-method.md`）

## 四、VOD 问题单写法（让反馈“可行动”）

一张高质量问题单应当回答 5 个问题：

| 要素 | 示例（本次实践） |
| --- | --- |
| 在什么场景下 | 使用 `huawei-cloud-computing-query` 查询计算类资源 |
| 期望什么 | 能一并查询 CCE 集群、节点池、节点状态 |
| 实际怎样 | 技能只覆盖 ECS / BMS / IMS / AS，不支持 CCE |
| 影响是什么 | 容器化业务需要切换到其他工具或控制台，排障链路割裂 |
| 建议怎么改 | 增加 CCE 只读查询子能力，或在 find-skills 中关联推荐 CCE 技能 |

注意事项：
- 只反馈**产品/服务**相关的问题，不要提交“test”“hello”这类空内容；
- 不要在问题单里粘贴 AK/SK、Token、内网地址等敏感信息；
- 同类问题先去重，再补充新的证据。

## 五、提示词模板

```text
# 找技能
帮我找找华为云有没有 <服务/动作> 的技能？

# 看详情并安装
请介绍技能 <skill-name> 的功能点，并完成安装

# 提问题单
<skill-name> 覆盖 <已有能力>，但缺少 <缺失能力>，提交 VOD 反馈
```

## 六、可复用性

这套流程与具体服务无关，可直接用于任何华为云服务：把第 ① 步的服务名替换掉即可。找技能不浪费时间，提问题单不靠吐槽，形成“**用 → 反馈 → 改进 → 再用**”的闭环。
